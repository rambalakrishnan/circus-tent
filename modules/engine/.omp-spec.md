# .omp-spec.md — engine module (Learn-Run-Heal state machine, preflight)

## Purpose

The execution core: preflight session-validity checks (B3), the Run/Heal/Vision tier
state machine, upload steps (B4), checkpoints (D4), and idempotency resume (B2).
Coordinates all other modules — imports parser, persistence, llm, browser (for
rate-limiter reporting). No LLM calls except through the llm module.

## Public API (keep signatures exact)

### preflight.py

```python
async def check_session(page: Any, url: str, marker: str,
                        timeout_ms: int = 20000) -> tuple[bool, str]
# navigate url; wait load; marker present in pruned DOM text → (True, "").
# marker absent → (False, "SESSION_EXPIRED"). nav failure → (False, "PREFLIGHT_ERROR").
# url=="" or marker=="" → (True, "") (preflight disabled).
```

### state_machine.py

```python
StepType = Literal["navigate", "fill", "click", "select", "wait", "extract",
                   "assert", "upload", "checkpoint"]

@dataclass(frozen=True)
class Step:
    id: str
    type: StepType
    # optional fields per type:
    url: str | None = None                       # navigate
    value: str | None = None                     # fill/select text
    selector_ref: str | None = None              # cache lookup id
    selector: str | None = None                  # inline selector (when no cache)
    strategy: str = "css"                        # "css" | "xpath"
    fallback_text: str = ""                      # human description (heal/vision)
    side_effecting: bool = False                 # at-most-once (B2)
    milliseconds: int | None = None              # wait
    text: str | None = None                      # assert expected text
    query: str | None = None                     # extract BM25 query
    schema: dict | None = None                   # extract schema
    file_ref: str | None = None                  # upload: path or object-store URI
    mode: str = "direct"                         # upload: "direct" | "dnd"
    mime_types: tuple[str, ...] = ()             # upload allowlist
    max_bytes: int = 5_242_880                   # upload size limit (5 MiB)
    note: str = ""                               # checkpoint note

@dataclass(frozen=True)
class StepResult:
    id: str
    status: str            # ok | healed | vision | failed | skipped
    tier: int | None       # 1 | 2 | 3 | None (skipped/checkpoint)
    selector: str | None   # selector ultimately used (or None)
    error: str | None
    duration_ms: int

@dataclass(frozen=True)
class RunResult:
    run_id: str
    idempotency_key: str
    status: str            # completed | failed | resumed
    resumed_from: int | None    # step index resumed at (None = fresh)
    steps: tuple[StepResult, ...]
    extracted: Any | None
    schema_incomplete: bool
    stabilization_partial: bool
    session: str           # "ok" | "SESSION_EXPIRED" | "PREFLIGHT_ERROR" | "disabled"

class ExecutionEngine:
    def __init__(self, cluster: ClusterManager, caches: SelectorCacheStore,
                 coord_caches: CoordinateCacheStore, model_client: ModelClient,
                 ledger: ExecutionLedger, budgets: BudgetManager,
                 challenge_resolver: ChallengeResolver | None,
                 metrics: Metrics, logger: logging.Logger,
                 upload_root: Path | None = None) -> None
    async def run(self, req: RunRequestLike) -> RunResult
    async def extract_url(self, domain: str, url: str, query: str | None,
                          schema: dict | None) -> ExtractionResult
    def selector_cache_for(self, domain: str) -> SelectorCache
    def coordinate_cache_for(self, domain: str) -> CoordinateCache
```

`SelectorCacheStore` / `CoordinateCacheStore` are thin dict-like facades keyed by
domain (this module may own them as small helper classes in state_machine.py).

## Tier semantics (binding)

**Entry:** resolve shard by domain; shard-level preflight first (B3) — on
`SESSION_EXPIRED` the whole run fails fast with `session` set and a
`session_expired` event emitted (logger + metrics), no steps executed.

**Resume (B2/D4):** ledger lookup by idempotency_key. Existing run with status
"running" or "failed" → resume from last checkpoint index (skip all steps before it,
marking them `skipped`; steps after are re-run; completed side-effecting steps are
NEVER re-executed — if a completed side-effecting step's index ≤ checkpoint, it stays
`ok` in the ledger and is not replayed). Existing run with status "completed" and
identical step ids → return the stored result (no re-execution). Same key, DIFFERENT
step list, terminal state → engine raises IdempotencyConflict (API maps to
`IDEMPOTENCY_CONFLICT`).

**Tier 1 — Run:** look up `selector_ref` (or inline selector) in the domain cache.
Execute with timeout (default 10s) catching TimeoutError, ElementNotInteractableError,
PlaywrightError. Success → `record_hit`. Unknown step type → step failure (schema
error, never a 500).

**Tier 2 — Heal:** on Tier-1 failure: if `budgets.circuit_open(shard)` → skip to
Tier 3 (no tokens). Else prune page (HEAL profile), call `model_client.heal(...)`,
validate response (selector+strategy non-null), retry the native op. Success →
`record_heal` + `budgets.record_step_outcome(shard, healed=True)`, status `healed`,
tier 2. Failure → Tier 3.

**Tier 3 — Vision:** localized screenshot: locate the step's target container
(nearest ancestor of the failed selector's last-known box, or body) via
`element.bounding_box()`; `page.screenshot(clip=box padded 100px)`; dHash the PNG;
coordinate cache hit (same viewport) → click box center; miss → `model_client.locate`
→ click box center → record to cache. Vision failure → step `failed` with
`VISION_FAILED`. Budgets charged before the vision call; vision circuit is per-shard
via `circuit_open` (same breaker).

**Extract steps:** stabilize + prune + `extract_page`; results land in
`RunResult.extracted`; `stabilization_partial` / `schema_incomplete` propagate.

**Assert steps:** pruned text contains `text` (case-insensitive substring) → ok else
step failure with the mismatch snippet (≤200 chars) in error.

**Upload steps (B4):** `file_ref` must be a local filesystem path under the
configured `upload_root` (or an explicitly allowed absolute path) — object-store URIs
raise a clear "not implemented" step error at v1. Enforce `max_bytes` and `mime_types`
(by extension + sniffed magic bytes). `direct`: `page.set_input_files(selector, path)`.
`dnd`: locate the drop zone, then dispatch synthetic drag events with a DataTransfer
containing the File (construct via page.evaluate; Workday-style zones need
dragenter → dragover → drop). Both modes require the target input/zone to exist;
failure follows the tier ladder like any step.

**Checkpoint steps:** record into ledger (`record_checkpoint`), status `ok`, tier None.

**Rate limiter reporting:** after every navigation and after each step that triggers
a request, report status via `cluster.report_response(domain, status, is_challenge)`;
`is_challenge` = challenge_resolver detected a challenge page. 429/403/503 from the
target → the rate limiter's backoff engages (B6); the engine surfaces
`RATE_LIMITED` step errors with Retry-After semantics at the API layer.

**Upload + side_effecting:** upload steps are implicitly side-effecting for resume
purposes? No — uploads are resumable-safe only if the form persisted; treat `upload`
as replayable but NEVER replay a `side_effecting: true` step after completion.

## Edge cases

- Steps referencing a `selector_ref` with no cache entry AND no inline selector →
  Tier 2 directly (with empty failed_selector), then Tier 3.
- Preflight URL unreachable (DNS/offline) → PREFLIGHT_ERROR, run fails fast.
- Checkpoint with no prior steps → records index 0.
- `extract` step schema satisfied → structured in `extracted`; unsatisfied →
  `schema_incomplete` True and best-effort partial.
